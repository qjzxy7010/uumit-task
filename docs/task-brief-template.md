# 任务书模板

> 发包方写。放在 `tasks/<order_no>/brief.md`。
> 目标：承接方读完**不需要再问任何问题**就能开工。

---

## 模板（照抄后填空）

```markdown
# 任务书 · <order_no>

## 一、基本信息

| 项 | 内容 |
|---|---|
| UUMit 订单号 | ORD... |
| 任务标题 | （平台原文标题） |
| 悬赏 | xxx UT |
| 外部截止 | YYYY-MM-DD HH:MM (GMT+8) |
| 内部截止 | YYYY-MM-DD HH:MM (GMT+8) ← 必须早于外部截止 12h |
| 交付物类型 | 视频 / 音频 / 图片 / 其他 |

## 二、平台原始要求（逐字照抄，不要改写）

> （把 UUMit 任务描述原文粘贴在这里，保留原文措辞）

平台声明的交付物：
- （原文写的 deliverable 列表）

## 三、内容要求（要做什么）

（把模糊的原文要求，转成可执行的描述。示例：）

- 主题：xxx
- 时长 / 篇幅：xxx
- 结构 / 分段：
  - 0-3s  ...
  - 3-8s  ...
- 必须包含的元素：...
- 允许的自由度：...

## 四、技术规格

见同目录 `spec.json`。摘要：

| 项 | 值 |
|---|---|
| 容器格式 | mp4 |
| 时长 | 20s（可接受 19–21s） |
| 分辨率 | 1920×1080 |
| 帧率 | 25 或 30 fps |
| 视频编码 | H.264 (yuv420p) |
| 音频编码 | AAC 48kHz 立体声 |
| 文件上限 | ≤ 100 MB |
| 文件名 | 城市夜景延时混剪.mp4 |

## 五、硬性约束（违反 = 验收不通过）

- [ ] 素材必须免版权（royalty-free / CC0 / 公共领域）
- [ ] 成品无任何水印 / logo / 台标 / 字幕条 / 第三方账号名
- [ ] 不得使用有版权争议的音乐
- [ ] 不得包含违法、侵权或平台禁止的内容

## 六、验收标准（我会逐条查）

- [ ] 文件存在且格式正确、能正常播放/打开
- [ ] 技术规格全部达标（对照 spec.json）
- [ ] 内容确实回应了「平台原始要求」，不是擦边凑数
- [ ] 无版权风险、无水印
- [ ] 可通过 UUMit 平台前置过滤

## 七、怎么交

1. 成品放到 `deliverables/<order_no>/<文件名>`
2. commit message：`deliver: <order_no> <文件名>`
3. 把 `tasks/<order_no>/status.json` 的 `state` 改为 `submitted`

## 八、备注

（可放参考链接、风格参考、注意事项、已知坑）
```

## 写任务书的三条原则

1. **不要照抄平台原文就完事** —— 平台原文常常很模糊（如"配节奏感音乐"）。你的职责是把它**翻译成可执行、可验收的规格**。
2. **规格必须可验证** —— 写"时长为 20 秒"而不是"时长合适"；写"1920×1080"而不是"高清"。验收时要能一条条打勾。
3. **写清红线** —— 版权、水印是最常见的打回原因，必须在任务书里显式列出，不能让承接方猜。

---

## 常见需澄清的模糊需求 → 可执行规格

| 平台原话 | 转成 |
|---|---|
| "高清" | 1920×1080 或以上 |
| "有节奏感音乐" | 电子/律动类纯音乐，四拍鼓点清晰，与画面切换同步 |
| "简洁" | ≤ N 字 / ≤ M 秒 / 单页 |
| "专业" | 含行业术语表、引用来源、可复核数据 |
| "配图" | N 张，1920×1080，免版权，风格统一 |
