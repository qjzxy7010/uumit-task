# 验收清单

> 发包方（本 Agent）逐单执行。结论写入 `reviews/<order_no>.md`。
> **原则：宁可打回，不要交不合格的活** —— 平台会记录账号信用。

---

## A. 文件完整性

- [ ] `deliverables/<order_no>/` 下有文件
- [ ] 文件名与 `spec.json` 的 `filename` 一致
- [ ] 体积 ≤ 100 MB，且 > 0
- [ ] 能正常打开 / 播放（不是损坏文件、不是空壳）

## B. 技术规格（对照 spec.json 逐项）

- [ ] 容器格式正确（mp4 / mp3 / png …）
- [ ] 时长在允许区间内
- [ ] 分辨率达标
- [ ] 编码符合要求（H.264 + AAC / MP3 ≥192kbps …）
- [ ] 帧率、采样率、声道数达标

## C. 内容合规（对照 brief.md 的「内容要求」）

- [ ] 成品**确实回应了订单的真实需求**（不是擦边、不是凑数）
- [ ] 要求的必含元素都在
- [ ] 结构 / 分段符合要求
- [ ] 没有明显机器劣质感（素材生硬拼接、音画不同拍、爆音）

## D. 版权与洁癖

- [ ] 无任何水印 / logo / 台标 / 字幕条 / 第三方账号名
- [ ] 素材为免版权 / CC0 / 公共领域
- [ ] 音乐有可商用授权
- [ ] 无他人肖像 / 商标侵权风险

## E. 平台前置过滤预判

平台在提交时同步检查，命中会当场 400：

- [ ] 不会被判 `DELIVERABLE_FORMAT_MISMATCH`
      （清一色 md/txt 但任务要求非文本产物）
- [ ] 不会被判 `DELIVERABLE_UNCHANGED_RESUBMIT`
      （返工时与上次被打回内容完全一致）

## F. 反规避（必查）

- [ ] 不只看"规格达标"——问自己：**如果我是买家，收到这个会不会觉得被糊弄？**
- [ ] 特别警惕：用一张图重复、用测试素材充数、时长达标但内容空洞

## 返工规则

- 第 1 次不通过：写明原因，承接方修改重传（`revision` +1）
- **连续 2 次不通过**：升级人工，不再自动重试
- 每次返工在同一个 review 文件追加新的一节，保留历史，不要覆盖
