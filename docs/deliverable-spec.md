# 交付规格与硬性约束

> **承接方必读。** 本文是所有任务的通用约束；每个任务的具体规格以 `tasks/<order_no>/spec.json` 为准。

---

## 1. 交付物放哪里

```
deliverables/<order_no>/<文件名>
```

- `<order_no>` = UUMit 订单号（任务书里写了）
- `<文件名>` = **必须与 `spec.json` 的 `filename` 字段完全一致**
- 一个订单一个目录；不要把多个订单的产物混放

---

## 2. 交付格式（按订单类型）

### 视频类

| 项 | 要求 |
|---|---|
| 容器 | MP4 |
| 视频编码 | H.264（`yuv420p`，保证兼容性） |
| 音频编码 | AAC，48kHz，立体声 |
| 分辨率 | 默认 1920×1080（16:9） |
| 帧率 | 25 或 30 fps |
| 时长 | 按 spec.json（允许 ±1s 误差，越准越好） |
| 体积 | ≤ 100 MB |

### 音频类

| 项 | 要求 |
|---|---|
| 容器 | MP3（默认）或 WAV |
| 采样率 | 44.1kHz 或 48kHz |
| 声道 | 立体声 |
| 码率 | MP3 ≥ 192 kbps |
| 时长 | 按 spec.json |
| 体积 | ≤ 100 MB |

### 图片类

| 项 | 要求 |
|---|---|
| 格式 | PNG（需透明）或 JPG |
| 分辨率 | ≥ 1920px 长边 |
| 色彩 | sRGB |
| 体积 | ≤ 100 MB |

---

## 3. 硬性约束（违反即打回）

- [ ] **版权干净**：只使用免版权 / CC0 / 公共领域素材；音乐必须有明确可商用授权
- [ ] **无水印**：无平台水印、logo、台标、字幕条、第三方账号名、试听标记
- [ ] **无侵权**：不使用他人肖像、商标、受保护作品（除非有授权）
- [ ] **内容合规**：不含违法、暴力、色情、政治敏感、平台禁止内容
- [ ] **规格达标**：格式 / 时长 / 分辨率 / 编码 / 体积符合 spec.json

---

## 4. 单文件 100 MB 上限的替代方案

GitHub 单文件上限 **100 MB**，UUMit 交付上限也是 **100 MB**。超限时：

| 方案 | 说明 |
|---|---|
| **压缩** | 优先：降码率 / 降分辨率到规格允许的最低值 |
| **分卷** | 拆成多个 <100MB 文件，在 `brief.md` 注明顺序 |
| **外部链接** | 放到可公开下载的网盘，在 `deliverables/<order_no>/download.md` 里写链接 + 校验值 |

> ⚠️ 不要用 Git LFS（当前令牌未配 LFS）。不要提交超过 100MB 的单文件，会被 GitHub 直接拒绝。

**校验值**：走外部链接或分卷时，必须提供 SHA256：
```
sha256sum <file>
```

---

## 5. 质量红线（比规格更重要）

规格达标 ≠ 验收通过。下列情形同样打回：

| 问题 | 说明 |
|---|---|
| **答非所问** | 成品没有回应订单的真实需求（例：要"城市夜景延时"，交了纯色测试片） |
| **明显机器感** | 素材拼接生硬、画面与音乐完全不对拍、音质爆音 |
| **凑数** | 用同一素材反复循环填够时长 |
| **规格边缘** | 时长/分辨率刚好卡在下限，导致实际观感不达标 |

## 6. 提交前的自检

```
# 文件在不在、多大
ls -la deliverables/<order_no>/

# 视频/音频：看规格（有 ffprobe 时）
ffprobe -v error -show_entries format=duration,size,bit_rate -show_entries stream=codec_name,width,height,sample_rate,channels -of default=noprint_wrappers=1 <file>

# 校验值（走外链/分卷时必需）
sha256sum <file>
```

**没有 ffprobe 也没关系**：用播放器打开确认能播、时长对、无异常即可；实在拿不准就在 PR/issue 里说明，别赌。

---

## 7. 提交格式

```
git add deliverables/<order_no>/<文件名>
git commit -m "deliver: <order_no> <文件名>"
git push
```

然后改 `tasks/<order_no>/status.json`：`state` → `"submitted"`。

---

## 8. 不确定时怎么办

- 先读 `tasks/<order_no>/brief.md`（那里有内容要求与备注）
- 仍不确定 → 在仓库开 Issue（标题 `[Q] <order_no> ...`）提问，**不要凭猜开工**
- 记住：**交付不达标比不接更糟**（占用订单时效、影响账号信用）
